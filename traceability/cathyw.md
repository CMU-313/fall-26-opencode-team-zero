## Requirement changes

| ID | Original requirement (P3) | Revised requirement | Why it changed |
|---|---|---|---|
| R4 | Adding a file and then deleting it must bring the map back to its original state, as long as no other files change and OpenCode does not read any additional files. The P3 acceptance criteria also required the same names. | Adding a file and then deleting it must restore the deterministic repository map to its original state, provided no other files or session-referenced paths change. The restored state includes group and subgroup IDs, structural titles, paths, referenced paths, and ordering. | The rule-based grouping function is deterministic for a fixed inventory and referenced-path list, so this preserves the interviewees' expectation that a temporary file leaves no structural trace (C-5 to C-6, S-6 to S-7, O-5 to O-6). `/group` can subsequently replace group titles with model-generated names through `applyGroupNames`; identical names across separate model calls cannot be guaranteed or checked by a property of `analyzeRepositoryGroups`. The P3 target declaration already excluded model-generated names from its rule-based scope. |

The remaining six requirements are feasible and checkable as written against the rule-based map. The implementation filters exact ignored directory segments, puts root files in the `Project root` group, deduplicates normalized input paths, uses stable directory rules for workspace groups and subgroups, and retains file coverage in overflow groups and subgroups. Passing the corresponding properties still needs to be verified in Step 2.
