## Agent failure case (OpenCode)

On November 9, I asked OpenCode in local session ses_e3c77911effeRIjtmXDFTFbGik: "Suggest one fast-check property for R4: adding then removing a temporary file restores the same deterministic repository group map. Use analyzeRepositoryGroups. Please only suggest code; do not edit files or run commands." Its response proposed a property headed "R4 variant: temporary file in different paths restores the map" with an inventory generator capped at 10 paths. The central suggested assertions were:

    const before = analyzeRepositoryGroups(inventory, referenced)
    const inventoryWithTemp = [...inventory, tempPath]
    const during = analyzeRepositoryGroups(inventoryWithTemp, referenced)
    const inventoryAfter = inventoryWithTemp.filter(p => p !== tempPath)
    const after = analyzeRepositoryGroups(inventoryAfter, referenced)
    expect(after).toEqual(before)
    expect(JSON.stringify(after)).toBe(JSON.stringify(before))
    expect(after.find(g => g.files.includes(tempPath))).toBeUndefined()

The reply also checked that the temporary path was absent from subgroups after removal. It calculated the during map but did not assert that the new file appeared in it. Its code placed fast-check options in the wrong call and used a nested-array includes check for subgroup files; the executable reproduction corrected the call shape, kept the original generators and assertions, and retained the 10-path bound.

**Prediction recorded before testing:** Stryker's mutant changing the subgroup overflow title at repository-functionality.ts line 107 from "Other areas" to an empty string will survive the OpenCode suggestion. Its inventory has at most 10 files, below the 20-subgroup overflow threshold, and a before/after comparison would accept the same wrong title on both sides even at the threshold. The strengthened R1/R9 overflow property checks the title against an independent expected value and should kill it.

**Overflow-title reproduction:** The executable adaptation of the OpenCode suggestion passed on the original code (1/1) and passed with the Stryker title mutant (1/1). The strengthened R1/R9 overflow properties failed at 29, 30, 31, and 50 groups (4 failures), while the original R4 property still passed. This shows that its 10-path generator never exercises overflow and its round-trip oracle cannot validate an independently correct title.

**A1 prediction recorded before testing:** A separate hand-written mutant that filters out every Markdown file should survive the OpenCode suggestion because its only assertions compare the map before and after deletion; the calculated map during addition is unused. My existing R4 property is stronger than OpenCode's suggestion because it asserts that the temporary Markdown file appears during the addition, so it should kill A1.

**A1 observed result:** The executable adaptation of OpenCode's suggestion passed against A1 (1/1, 200 generated runs). My existing R4 property in the main suite failed immediately; fast-check shrank the counterexample to a temporary docs/a.md file. That property includes expect(groupFiles(during)).toContain(temporary) and the parallel subgroup assertion, supplying the missing independent check of the during state. The full suite reported 24 failures and 1 pass against A1, then the source was restored. I reran the reproduction with OpenCode's original generators and assertions, correcting only syntax so it could execute. The baseline and A1 runs both passed (1/1 each, 200 generated cases). The temporary test file was removed after reproduction; A1.patch preserves the mutant. A1 is a separate agent-failure demonstration in addition to the five required H1–H5 hand-written mutants.

It also mutated source-root labels, modules/services workspace labels, and the default referenced-path value; those exact behaviors were not specified by R1–R7, so I removed those lines from the final requirement-scoped configuration. This was a scope change, not an equivalent-mutant claim. Several remaining survivors changed overflow IDs, titles, or roots without changing file coverage. I added R9 as a P5-derived requirement and strengthened the existing R1 boundary property to assert the independent expected overflow metadata at 19, 20, 21, and 25 subgroups and at 29, 30, 31, and 50 groups. The scoped rerun then killed 83 of 85 mutants (97.65%); its report is saved as mutants/cathyw/mutation-before-R8.html.

The two remaining survivors both changed the workspace conditional at line 32: replacing its condition with true, or replacing logical AND with OR. They split ordinary paths such as docs/guides/README.md and docs/notes/README.md into separate groups. R1–R7 checked full file coverage and named workspace groups but did not require ordinary paths to share the docs group. This was a plausible grouping bug I had not considered. I added R8 as a P5-derived requirement, then added a generated invariant over ordinary root names and distinct child folders. Both survivors were killed on rerun.

The final report has 85 killed, 0 survived, 0 timed out, and 0 errors: raw score 100.00%. I claim no equivalent mutants, so the score with equivalent mutants excluded is also 100.00%. The exploratory 82.65% score is not directly comparable to 100.00%, because its mutation scope was broader; the comparable before/after scores are 97.65% and 100.00% on the same 85 mutants.

The hand-written patches targeted developer-level mistakes Stryker did not generate exactly: H1 removed one ignored directory name rather than substituting an empty string; H2 removed input deduplication rather than deleting a surrounding expression; H3 removed the final tie-break comparison; H4 shifted the overflow boundary by one rather than Stryker's available arithmetic replacements; and H5 grouped every workspace under only its first directory. Hand-written mutants were tied to specific requirements and plausible maintenance errors; Stryker systematically explored individual expressions and showed where independent structural oracles were missing.
